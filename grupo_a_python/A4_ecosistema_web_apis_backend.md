# Categoría A4: Ecosistema Web, APIs y Backend (2000 – 2025)

| # | Hito / Pista (Frente) | Año (Reverso) | Creador / Bonus | Dato Curioso |
| :--- | :--- | :---: | :--- | :--- |
| **#A4-001** | Liberación de **Zope 2**, el servidor de aplicaciones pionero que introdujo la base de datos orientada a objetos *ZODB* y publicación web transparente. | **2000** | *Jim Fulton* (*Digital Creations*) | Permitió almacenar objetos Python directamente en disco sin escribir una sola línea de SQL, impulsando las primeras arquitecturas web corporativas en el lenguaje. |
| **#A4-002** | Nacimiento de **Twisted**, el framework asíncrono conducido por eventos (*event-driven networking*) antes de que existieran corrutinas nativas en Python. | **2001** | *Glyph Lefkowitz* | Glyph lo programó originalmente para dar vida a un videojuego online multijugador; su arquitectura basada en objetos *Deferred* inspiró las promesas modernas en JavaScript. |
| **#A4-003** | Lanzamiento de **Plone**, el sistema de gestión de contenidos (*CMS*) de código abierto construido sobre Zope y centrado en la accesibilidad. | **2001** | *Alan Runyan*, *Alexander Limi* y *Vidar Andersen* | Fue adoptado por organismos de máxima seguridad como la **CIA**, la **NASA** y gobiernos de todo el mundo debido a su implacable arquitectura de permisos. |
| **#A4-004** | Aprobación del **PEP 333**, definiendo la especificación estándar **WSGI** (*Web Server Gateway Interface*) para desacoplar servidores de frameworks. | **2003** | *Phillip J. Eby* | Terminó con la anarquía donde cada framework web requería su propio módulo para Apache, permitiendo que cualquier app corriera sobre cualquier servidor web. |
| **#A4-005** | Publicación en código abierto de **Django**, el framework con "baterías incluidas" que incorporó un ORM relacional y panel de administración autogenerado. | **2005** | *Adrian Holovaty* y *Simon Willison* | Desarrollado contra reloj en la redacción del diario *Lawrence Journal-World*, fue bautizado en tributo al legendario guitarrista de jazz manouche **Django Reinhardt**. |
| **#A4-006** | Debut de **TurboGears**, un megaframework que articuló las mejores piezas existentes (*CherryPy*, *SQLObject*, *Kid* y *Mochikit*) en una solución unificada. | **2005** | *Kevin Dangoor* | Demostró el poder de ensamblar librerías de la comunidad en lugar de reinventar la rueda, marcando la era de oro de los frameworks modulares en Python 2. |
| **#A4-007** | Creación de **SQLAlchemy**, el sofisticado kit de herramientas SQL y mapeador relacional de objetos (*ORM*) para bases de datos empresariales. | **2006** | *Mike Bayer* | Adoptó el patrón *Data Mapper* en lugar del popular *Active Record*, otorgando a los desarrolladores control milimétrico sobre consultas y transacciones complejas. |
| **#A4-008** | Aparición de **Werkzeug**, una completa biblioteca de utilidades WSGI para gestionar enrutamiento HTTP, cookies y depuración interactiva. | **2007** | *Armin Ronacher* (*Pocoo Team*) | Su consola de depuración en el navegador con capacidad de ejecutar código en vivo dentro de la traza de error causó fascinación mundial en conferencias técnicas. |
| **#A4-009** | Lanzamiento del motor de plantillas **Jinja2**, optimizado para compilar código HTML directamente a código Python en memoria. | **2008** | *Armin Ronacher* | Tomó prestada la elegante sintaxis de llaves `{{ variable }}` y `{% tag %}` de Django, perfeccionando su velocidad y seguridad con auto-escape automático. |
| **#A4-010** | Liberación en código abierto del servidor web y framework asíncrono **Tornado** tras la adquisición de *FriendFeed* por parte de Facebook. | **2009** | *Bret Taylor* (*FriendFeed / Facebook*) | Capaz de sostener decenas de miles de conexiones HTTP abiertas en tiempo real mediante sondeo *epoll*, popularizó las aplicaciones web de actualización instantánea. |
| **#A4-011** | Nacimiento de **Celery**, el sistema distribuido de colas de tareas asíncronas para procesamiento en segundo plano con brokers como RabbitMQ y Redis. | **2009** | *Ask Solem* | Se convirtió en el estándar indiscutible de la industria para descargar tareas pesadas de emails, reportes y machine learning fuera del ciclo de respuesta HTTP. |
| **#A4-012** | Presentación de **Flask**, el microframework minimalista que inició como una broma del día de los inocentes (*April Fools' Joke*). | **2010** | *Armin Ronacher* | Empaquetó *Werkzeug* y *Jinja* dentro de un archivo `.zip` ejecutable como sátira contra los frameworks monolíticos; la acogida fue tan entusiasta que se transformó en un proyecto real. |
| **#A4-013** | Creación de **Gunicorn** (*Green Unicorn*), el servidor HTTP WSGI basado en el modelo de procesos pre-forking portado desde el ecosistema Ruby. | **2010** | *Benoît Chesneau* | Su extrema sencillez operativa y bajo consumo de recursos lo erigieron en el estándar por defecto para desplegar contenedores Python en producción. |
| **#A4-014** | Introducción de **Gevent**, una librería de concurrencia de alto rendimiento basada en *greenlets* y el bucle de eventos *libev*. | **2010** | *Denis Bilenko* | Permitía convertir mágicamente código bloqueante síncrono en asíncrono sin reescribir funciones, aplicando parches en caliente (*monkey patching*) al socket estándar. |
| **#A4-015** | Publicación de **Bottle**, un microframework web completo contenido enteramente dentro de un único archivo fuente `bottle.py` sin dependencias. | **2010** | *Marcel Hellkamp* | Se convirtió en la herramienta favorita para microservicios ligeros, prototipos de hardware embebido y utilitarios donde desplegar dependencias era inviable. |
| **#A4-016** | Consagración de **Requests** bajo el lema *"HTTP for Humans"*, redefiniendo para siempre la ergonomía de las librerías cliente en Python. | **2011** | *Kenneth Reitz* | Desterró la tortuosa e ininteligible API estándar de `urllib2`, permitiendo realizar peticiones con sintaxis cristalina como `requests.get(url, auth=...)`. |
| **#A4-017** | Debut de **Django REST Framework** (**DRF**), brindando serializadores avanzados y vistas navegables para construir APIs RESTful profesionales. | **2011** | *Tom Christie* | Su interfaz HTML interactiva para explorar endpoints y enviar payloads directamente desde el navegador transformó el desarrollo y testeo de APIs backend. |
| **#A4-018** | Presentación de **Pyramid**, el framework modular nacido de la fusión de *repoze.bfg* y el proyecto *Pylons*. | **2011** | *Chris McDonough* | Destacó por su filosofía de configuración flexible, seguridad basada en listas de control de acceso (*ACLs*) y capacidad para crecer desde microapps hasta portales gigantes. |
| **#A4-019** | Lanzamiento de **Falcon**, un microframework WSGI enfocado obsesivamente en la baja latencia y el rendimiento extremo para APIs de nube. | **2013** | *Kurt Griffiths* | Evitó intencionadamente abstracciones pesadas para responder peticiones JSON a máxima velocidad, procesando hasta 30 veces más requests por segundo que los frameworks tradicionales. |
| **#A4-020** | Creación de **aiohttp**, proveyendo cliente y servidor HTTP asíncrono construido sobre el nuevo bucle de eventos `asyncio` de Python 3.4. | **2013** | *Nikolay Kim* y *Andrew Svetlov* | Fue la primera gran librería en demostrar el potencial de las corrutinas para consumir y exponer APIs asíncronas con miles de conexiones abiertas. |
| **#A4-021** | Debut de **Sanic**, un framework web asíncrono diseñado para volar sobre el bucle ultrarrápido *uvloop* emulando la sintaxis accesible de Flask. | **2016** | *Yun Xu* | Su lema *"Build fast. Run even faster."* cautivó a desarrolladores que querían el rendimiento de Node.js o Go sin renunciar a la expresividad de Python. |
| **#A4-022** | Lanzamiento de **uvloop**, una reimplementación del bucle de eventos de `asyncio` programada en Cython sobre la biblioteca en C **libuv**. | **2016** | *Yury Selivanov* (*MagicStack*) | Demostró que un bucle de eventos en Python podía ser entre 2 y 4 veces más rápido que el de Node.js, superando los 100,000 requests por segundo en benchmarks. |
| **#A4-023** | Creación de **Django Channels**, extendiendo el corazón síncrono de Django para admitir WebSockets, chats y tareas en tiempo real. | **2016** | *Andrew Godwin* | Introdujo el concepto de capas de canales (*channel layers*) sobre Redis, permitiendo a Django cruzar la frontera de las arquitecturas HTTP clásicas. |
| **#A4-024** | Publicación de la especificación **ASGI** (*Asynchronous Server Gateway Interface*), superando los límites unidireccionales de WSGI. | **2018** | *Andrew Godwin* | Diseñada para soportar protocolos bidireccionales continuos como WebSockets y HTTP/2 sobre bucles asíncronos nativos, marcando el estándar del backend moderno. |
| **#A4-025** | Lanzamiento del toolkit y microframework **Starlette**, concebido como el pilar fundamental para la nueva era de aplicaciones ASGI. | **2018** | *Tom Christie* | Aportó manejo robusto de WebSockets, middleware asíncrono y streaming de datos con cero dependencias externas pesadas. |
| **#A4-026** | Creación de **Uvicorn**, el servidor web ASGI de alto rendimiento basado en *uvloop* y el parser de peticiones en C *httptools*. | **2018** | *Tom Christie* | Se convirtió de inmediato en el servidor de referencia para ejecutar frameworks modernos de Python en plataformas contenerizadas y orquestadores. |
| **#A4-027** | Nacimiento de **FastAPI**, articulando *Starlette*, *Pydantic* y tipado estático con generación automática de esquemas **OpenAPI**. | **2018** | *Sebastián Ramírez* (*tiangolo*) | Revolucionó el ecosistema mundial de APIs; su documentación interactiva autogenerada en Swagger UI y su validación estricta lo catapultaron al top de popularidad global. |
| **#A4-028** | Presentación de **HTTPX**, el cliente HTTP de última generación con soporte unificado síncrono y asíncrono, y compatibilidad nativa con **HTTP/2**. | **2019** | *Tom Christie* (*Encode*) | Diseñado como el sucesor espiritual de *Requests*, resolvió la falta de soporte HTTP/2 y de llamadas con `await` en clientes HTTP para Python. |
| **#A4-029** | Lanzamiento de **Pydantic v1**, popularizando la validación de esquemas de datos y serialización basada exclusivamente en pistas de tipado estándar. | **2020** | *Samuel Colvin* | Transformó el parsing de payloads JSON al convertir anotaciones ordinarias de Python (`name: str`, `age: int`) en validadores rigurosos en tiempo de ejecución. |
| **#A4-030** | Creación de **Litestar** (originalmente *Starlite*), un framework ASGI altamente configurable con inyección de dependencias y validación estricta de tipos. | **2021** | *Cody Fincher* y *Peter Schutt* | Ofreció una arquitectura orientada a la mantenibilidad en equipos corporativos, implementando controladores basados en clases y serialización multiproveedor. |
| **#A4-031** | Incorporación de interfaz asíncrona nativa en el ORM de **Django 4.2**, permitiendo realizar consultas con `await` sin bloquear hilos. | **2023** | *Carlton Gibson* y *Mariusz Felisiak* | Marcó el culmen de una década de trabajo para modernizar las tripas de Django, permitiendo mezclar vistas asíncronas con transacciones de base de datos directas. |
| **#A4-032** | Reescritura integral del motor de **Pydantic v2** en lenguaje **Rust** a través de la librería interna `pydantic-core`. | **2023** | *Samuel Colvin* (*Pydantic Inc.*) | Multiplicó la velocidad de validación y serialización de JSON entre 5x y 50x, demostrando la viabilidad de acelerar Python delegando cuellos de botella en Rust. |
| **#A4-033** | Presentación de **Granian**, un servidor HTTP para Python escrito enteramente en **Rust** que implementa interfaces WSGI, ASGI y RSGI. | **2023** | *Sebastiano Ferraris* | Empleó el runtime asíncrono *Tokio* y el parser *Hyper*, registrando tasas de procesamiento superiores a cualquier servidor Python puro en la historia. |
| **#A4-034** | Debut de **Robyn**, un framework web asíncrono escrito en Python y propulsado internamente por un motor multihilo en Rust. | **2024** | *Sanskar Jethi* | Permitió omitir las complejidades del GIL en el manejo de conexiones entrantes al despachar las llamadas de red directamente en los hilos nativos del runtime de Rust. |
| **#A4-035** | Despliegue de la suite oficial **FastAPI CLI**, aportando comandos integrados para desarrollo local y despliegue a producción con un solo comando. | **2024** | *Sebastián Ramírez* | Simplificó el flujo de trabajo de millones de desarrolladores, desterrando configuraciones complejas de servidores en entornos de testing e integración continua. |
| **#A4-036** | Liberación de **Litestar 3.0**, introduciendo soporte integral para streaming de eventos de IA (*Server-Sent Events*) y especificación **OpenAPI 3.1**. | **2025** | *Litestar Organization* | Optimizó la canalización de tokens de LLMs hacia clientes frontend, consolidándose como la plataforma preferida para backend de agentes inteligentes en Python. |
