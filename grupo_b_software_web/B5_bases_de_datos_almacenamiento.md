# Categoría B5: Bases de Datos y Almacenamiento (1979 – 2025)

| # | Hito / Pista (Frente) | Año (Reverso) | Creador / Bonus | Dato Curioso |
| :--- | :--- | :---: | :--- | :--- |
| **#B5-001** | Publicación del paper fundacional sobre el modelo relacional de datos por parte de un investigador de IBM. | **1970** | *Edgar F. Codd* (*IBM Research*) | Los directivos de IBM intentaron enterrar su investigación durante años porque amenazaba el lucrativo negocio de su sistema de bases de datos jerárquico *IMS*. |
| **#B5-002** | Creación del lenguaje **SEQUEL** (posteriormente acortado a **SQL**) en el laboratorio de investigación de IBM en San José. | **1974** | *Donald Chamberlin* y *Raymond Boyce* | Tuvieron que retirar las letras intermedias de *SEQUEL* debido a que era una marca registrada de una compañía de aviones británica, adoptando el acrónimo *SQL*. |
| **#B5-003** | Lanzamiento comercial de **Oracle Version 2**, convirtiéndose en el primer sistema de gestión de bases de datos relacional con SQL del mercado. | **1979** | *Larry Ellison*, *Bob Miner* y *Ed Oates* (*RSI*) | Le llamaron "Versión 2" intencionadamente porque Ellison sabía que ninguna gran corporación compraría una "Versión 1.0" de un software empresarial crítico. |
| **#B5-004** | Inicio del proyecto **Postgres** en la Universidad de California en Berkeley como el sucesor de nueva generación de Ingres. | **1986** | *Michael Stonebraker* (*UC Berkeley*) | Su nombre original significaba literalmente *"Post-Ingres"*; Stonebraker introdujo tipos de datos complejos definibles por el usuario y herencia de tablas. |
| **#B5-005** | Nacimiento de **MySQL**, concebido como un motor relacional extremadamente rápido y ligero para bases de datos de páginas web. | **1995** | *Michael "Monty" Widenius* y *David Axmark* (*MySQL AB*) | Bautizado con el nombre de la hija primogénita de Monty, llamada **My**; años más tarde, cuando vendieron MySQL a Sun y crearon un fork libre, lo llamaron **MariaDB** por su segunda hija. |
| **#B5-006** | Presentación de **PostgreSQL 6.0**, marcando la refundación del proyecto con soporte SQL nativo completo impulsado por la comunidad libre. | **1997** | *PostgreSQL Global Development Group* | Los desarrolladores añadieron índices avanzados, claves foráneas y disparadores (*triggers*), convirtiéndolo con el tiempo en la base de datos de código abierto más respetada del mundo. |
| **#B5-007** | Creación de **SQLite**, un motor SQL embebido y contenido en una única librería en C sin necesidad de configuración ni procesos cliente-servidor. | **2000** | *D. Richard Hipp* | Hipp lo diseñó a bordo de un destructor de misiles guiados de la Marina de EE.UU. tras la frustración de ver caer servidores de base de datos durante maniobras militares. |
| **#B5-008** | Lanzamiento de **Memcached**, un sistema distribuido de caché en memoria RAM para acelerar la carga de sitios web dinámicos. | **2003** | *Brad Fitzpatrick* (*Danga Interactive*) | Programado originalmente en Perl para salvar de la lentitud a la plataforma social de blogs *LiveJournal*, fue reescrito de inmediato en C para soportar cientos de miles de peticiones. |
| **#B5-009** | Publicación del influyente paper de **Bigtable**, describiendo la base de datos distribuida de Google para almacenar petabytes de datos no estructurados. | **2006** | *Google* (*Fay Chang*, *Jeff Dean*, *Sanjay Ghemawat* et al.) | Inspiró a toda una generación de ingenieros en Silicon Valley, dando lugar a implementaciones libres como *Apache Cassandra* y *HBase* dentro del stack de Big Data. |
| **#B5-010** | Divulgación del paper de **Dynamo** por parte de Amazon, demostrando las ventajas de la consistencia eventual y el diseño NoSQL altamente disponible. | **2007** | *Amazon* (*Werner Vogels* et al.) | Nació tras una catástrofe en el *Black Friday* de 2004, donde el carrito de compras de Amazon colapsó bajo la lentitud de bases de datos relacionales tradicionales. |
| **#B5-011** | Lanzamiento de **Apache Cassandra** en código abierto por parte de ingenieros de Facebook para su función de búsqueda de mensajes. | **2008** | *Avinash Lakshman* y *Prashant Malik* (*Facebook*) | Combinó el modelo de datos tabular de Google Bigtable con la topología de nodos sin maestro central de Amazon Dynamo, logrando tolerancia a fallos total. |
| **#B5-012** | Nacimiento de **MongoDB**, apostando por el almacenamiento de documentos semiestructurados en formato binario **BSON** y esquemas dinámicos. | **2009** | *Eliot Horowitz*, *Dwight Merriman* y *Kevin Ryan* (*10gen*) | Su nombre proviene de la palabra *"humongous"* (descomunal); lideró la fiebre del movimiento NoSQL al permitir a desarrolladores guardar objetos JSON directamente sin migraciones. |
| **#B5-013** | Creación de **Redis** (*REmote DIctionary Server*), revolucionando el almacenamiento en memoria con estructuras de datos complejas nativas. | **2009** | *Salvatore Sanfilippo* (*antirez*) | Desarrollado en la pequeña localidad italiana de San Salvatore di Fitalia para escalar un servicio de analítica en tiempo real; destacó por su código C poético y ultracompacto. |
| **#B5-014** | Liberación en código abierto de **Apache Kafka**, una plataforma distribuida de streaming de eventos basada en un registro de anexado continuo (*append-only commit log*). | **2011** | *Jay Kreps*, *Neha Narkhede* y *Jun Rao* (*LinkedIn*) | Kreps eligió el nombre del autor literario **Franz Kafka** porque el software estaba obsesivamente optimizado para escribir datos a máxima velocidad. |
| **#B5-015** | Publicación del paper de **Spanner** por ingenieros de Google, resolviendo el Santo Grial de las bases de datos distribuidas globales con consistencia estricta. | **2012** | *Google* (*James Corbett* et al.) | Sincroniza relojes entre centros de datos de todo el planeta utilizando receptores GPS dedicados y relojes atómicos de rubidio (*TrueTime API*) para ordenar transacciones. |
| **#B5-016** | Apertura pública de **ClickHouse**, un sistema de gestión de bases de datos relacional orientado a columnas para analítica en tiempo real masiva (*OLAP*). | **2016** | *Yandex* (*Alexey Milovidov*) | Diseñado para analizar billones de eventos de clics de navegación por segundo, pulverizó los registros mundiales de velocidad en consultas agregadas masivas. |
| **#B5-017** | Nacimiento de **DuckDB**, concebido en el centro CWI de Ámsterdam como el equivalente de SQLite para analítica de datos en memoria y archivos Parquet. | **2019** | *Hannes Mühleisen* y *Mark Raasveldt* (*CWI*) | Permite consultar gigabytes de archivos de datos locales directamente desde Python o R con consultas vectorizadas sin configurar clusters pesados. |
| **#B5-018** | Presentación de **Neon**, introduciendo una arquitectura *Serverless* que desacopla el cómputo de la capa de almacenamiento en **PostgreSQL**. | **2021** | *Heikki Linnakangas* y equipo Neon | Permitió crear ramas de bases de datos (*database branching*) en microsegundos de forma análoga a una rama de Git, revolucionando entornos de pruebas y staging. |
| **#B5-019** | Consagración fulminante de la extensión **pgvector**, transformando a PostgreSQL en una base de datos vectorial para sistemas de inteligencia artificial generativa (*RAG*). | **2023** | *Andrew Kane* | Permitió a miles de startups almacenar y comparar *embeddings* numéricos de OpenAI sin necesidad de contratar bases de datos vectoriales dedicadas de terceros. |
| **#B5-020** | Fractura en el ecosistema de Redis tras el cambio de licencia de código abierto a licencias restrictivas de código disponible (*RSALv2*). | **2024** | *Redis Ltd.* y *Linux Foundation* | La comunidad y grandes empresas de nube respondieron de inmediato fundando la bifurcación **Valkey** bajo la tutela neutral de la *Linux Foundation*. |
